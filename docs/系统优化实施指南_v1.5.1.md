## 🚀 Phase 1: 数据库索引优化（1-2天）

### 步骤1.1: 备份数据库

```bash
# 备份整个数据库
mysqldump -u root -p --single-transaction --routines --triggers cardioguard > backup_$(date +%Y%m%d_%H%M%S).sql

# 验证备份文件
ls -lh backup_*.sql
```

### 步骤1.2: 执行索引优化脚本

```bash
# 连接到MySQL
mysql -u root -p

# 选择数据库
USE cardioguard;

# 执行优化脚本
source /path/to/cardio-guard-360/database/optimization_indexes.sql;

# 验证索引创建
SHOW INDEX FROM sys_user;
SHOW INDEX FROM device;
SHOW INDEX FROM ecg_multilead_record;
```

### 步骤1.3: 验证索引效果

```sql
-- 使用EXPLAIN分析典型查询
EXPLAIN SELECT * FROM ecg_multilead_record 
WHERE user_id = 100 AND status = 'COMPLETED' 
ORDER BY created_at DESC 
LIMIT 20;

-- 检查是否使用了idx_user_status_created索引
-- 预期结果: key列显示 idx_user_status_created
```

### 步骤1.4: 监控慢查询

```bash
# 查看慢查询日志
tail -f logs/cardioguard.log | grep "慢查询检测"

# 或者在MySQL中启用慢查询日志
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;  # 超过1秒的查询记录为慢查询
```

**验收标准：**
- ✅ 所有索引创建成功
- ✅ EXPLAIN显示使用新索引
- ✅ 慢查询数量减少50%以上

**验证配置生效：**

```bash
# 预期输出包含连接池初始化信息
```

### 步骤4.2: 应用JVM参数

**方式一：命令行启动**

```bash
java \
  -Xms2g \
  -Xmx2g \
  -XX:+UseG1GC \
  -XX:MaxGCPauseMillis=200 \
  -Xlog:gc*:file=/logs/gc.log:time,uptime:filecount=5,filesize=50M \
  -jar target/cardioguard-backend-1.0.0.jar
```

**方式二：使用jvm.options文件**

```bash
# 读取配置文件
export JAVA_OPTS=$(cat jvm.options | grep -v "^#" | tr '\n' ' ')

# 启动应用
java $JAVA_OPTS -jar target/cardioguard-backend-1.0.0.jar
```

**方式三：Docker部署**

更新`docker-compose.yml`：

```yaml
services:
  backend:
    environment:
      - JAVA_OPTS=-Xms2g -Xmx2g -XX:+UseG1GC -XX:MaxGCPauseMillis=200
```

**验收标准：**
- ✅ HikariCP连接池正常初始化

```python
# websocket_test.py
import asyncio
import websockets
import json

async def test_websocket_connection(user_id):
    uri = f"ws://localhost:8080/api/ws/health-monitor?userId={user_id}"
    async with websockets.connect(uri) as websocket:
        # 发送心跳
        await websocket.send(json.dumps({"type": "heartbeat"}))
        response = await websocket.recv()
        print(f"User {user_id}: {response}")

async def main():
    # 创建100个并发连接
    tasks = [test_websocket_connection(i) for i in range(100)]
    await asyncio.gather(*tasks)

asyncio.run(main())
```

## 🔧 故障排查

### 问题1: 索引创建失败

**症状：**
```
ERROR 1061 (42000): Duplicate key name 'idx_role_status'
```

**解决：**
```sql
-- 检查索引是否已存在
SHOW INDEX FROM sys_user WHERE Key_name = 'idx_role_status';

-- 如果已存在，跳过该索引
-- 或者先删除再创建
DROP INDEX idx_role_status ON sys_user;
```

### 问题2: Redis连接失败

**症状：**
```
org.springframework.data.redis.RedisConnectionFailureException
```

**解决：**
```bash
# 检查Redis是否运行
redis-cli ping

# 检查Redis配置
cat /etc/redis/redis.conf | grep bind

# 确保bind配置允许本地连接
# bind 127.0.0.1
```

### 问题3: 缓存未生效

**症状：**
每次请求都查询数据库，日志显示"缓存未命中"

**解决：**
```bash
# 1. 检查Redis中是否有数据
redis-cli KEYS "ecg:lead:config:*"

# 2. 检查Redis序列化配置
# 确保RedisTemplate使用正确的序列化器

# 3. 清除缓存重试
redis-cli FLUSHDB
# 重启应用，触发缓存预热
```

### 问题4: GC停顿时间过长

**症状：**
应用出现明显卡顿，日志显示GC停顿超过500ms

**解决：**
```bash
# 1. 增加堆内存
-Xms4g -Xmx4g

# 2. 调整G1参数
-XX:MaxGCPauseMillis=100  # 更激进的停顿目标
-XX:G1HeapRegionSize=32m  # 增大Region

# 3. 分析堆转储文件
jmap -dump:format=b,file=heap.hprof <pid>
# 使用MAT或VisualVM分析
```

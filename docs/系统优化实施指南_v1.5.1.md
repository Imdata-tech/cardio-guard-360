## 🚀 Phase 1: 数据库索引优化（1-2天）

### 步骤1.1: 备份数据库

#### 方式一：使用自动化脚本（推荐）

```bash
./database/execute_optimization.sh
```

脚本会自动完成备份和优化，备份文件保存在 `database/backups/backup_YYYYMMDD_HHMMSS.sql`

#### 方式二：手动备份

```bash
# 创建备份目录
mkdir -p database/backups

# 备份整个数据库
mysqldump -u root -p \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --hex-blob \
    cardioguard > database/backups/backup_$(date +%Y%m%d_%H%M%S).sql

# 验证备份文件
ls -lh database/backups/
wc -l database/backups/backup_*.sql
```

**备份参数说明：**
- `--single-transaction`: 保证备份一致性（InnoDB引擎）
- `--routines`: 包含存储过程和函数
- `--triggers`: 包含触发器
- `--events`: 包含事件调度器
- `--hex-blob`: 二进制数据以十六进制格式导出

### 步骤1.2: 执行索引优化脚本

#### 方式一：使用自动化脚本（推荐）

自动化脚本已包含此步骤，会自动执行。

```bash

mysql -u root -p
```

**EXPLAIN关键字段说明：**

- `Extra`: 额外信息（不应出现"Using filesort"或"Using temporary"）

### 步骤1.5: 监控慢查询

#### 启用慢查询日志

**方式一：在MySQL中动态启用**

```sql
-- 启用慢查询日志

-- 设置慢查询阈值（1秒）

-- 设置慢查询日志文件路径

-- 验证配置

SHOW VARIABLES LIKE 'long_query_time';
```

```ini
[mysqld]
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow-query.log
long_query_time = 1
log_queries_not_using_indexes = 1
```

然后重启MySQL服务：
```bash
sudo systemctl restart mysql
```

### 步骤3.4: 调整慢查询阈值（可选）

如果1秒阈值不合适，可以在`SqlPerformanceInterceptor.java`中调整：

```java
private static final long SLOW_QUERY_THRESHOLD = 500; // 改为500ms
```

或者通过配置文件动态配置（需要添加配置支持）：

```yaml
mybatis-plus:
```

```java
@Override
public void setProperties(Properties properties) {
    String threshold = properties.getProperty("slowQueryThreshold");
    if (threshold != null) {
        SLOW_QUERY_THRESHOLD = Long.parseLong(threshold);
    }
}
```

### 步骤5.3: WebSocket并发测试

创建Python测试脚本 `websocket_test.py`:

```python
import asyncio
import websockets
import json
import time

async def test_websocket_connection(user_id):
    """测试单个WebSocket连接"""
    uri = f"ws://localhost:8080/api/ws/health-monitor?userId={user_id}"
    try:
        async with websockets.connect(uri) as websocket:
            # 发送心跳
            await websocket.send(json.dumps({"type": "heartbeat"}))
            response = await asyncio.wait_for(websocket.recv(), timeout=5.0)
            return True
    except Exception as e:
        print(f"User {user_id} failed: {e}")
        return False

async def main():
    """创建多个并发连接"""
    num_connections = 100
    
    print(f"开始测试 {num_connections} 个WebSocket并发连接...")
    start_time = time.time()
    
    # 创建并发任务
    tasks = [test_websocket_connection(i) for i in range(num_connections)]
    results = await asyncio.gather(*tasks, return_exceptions=True)
    
    end_time = time.time()
    
    # 统计结果
    success_count = sum(1 for r in results if r is True)
    failed_count = num_connections - success_count
    
    print(f"\n测试结果:")
    print(f"总连接数: {num_connections}")
    print(f"成功: {success_count}")
    print(f"失败: {failed_count}")
    print(f"成功率: {success_count/num_connections*100:.2f}%")
    print(f"耗时: {end_time - start_time:.2f}秒")

if __name__ == "__main__":
    asyncio.run(main())
```

## 🔧 故障排查

### 问题1: 索引创建失败

**症状：**
```
ERROR 1061 (42000): Duplicate key name 'idx_role_status'
```

**原因：** 索引已存在

**解决：**
```sql
-- 检查索引是否已存在
SHOW INDEX FROM sys_user WHERE Key_name = 'idx_role_status';

-- 如果已存在，跳过该索引
-- 或者先删除再创建
DROP INDEX idx_role_status ON sys_user;
ALTER TABLE sys_user ADD INDEX idx_role_status (role, status);
```

### 问题2: Redis连接失败

**症状：**
```
org.springframework.data.redis.RedisConnectionFailureException: 
Unable to connect to Redis
```

**解决：**
```bash
# 1. 检查Redis是否运行
redis-cli ping
# 预期: PONG

# 2. 检查Redis配置
cat /etc/redis/redis.conf | grep bind
# 确保: bind 127.0.0.1

# 3. 检查防火墙
sudo ufw status
# 如果需要，允许6379端口
sudo ufw allow 6379

# 4. 重启Redis
sudo systemctl restart redis
```

### 问题3: 缓存未生效

**症状：** 每次请求都查询数据库，日志显示"缓存未命中"

**排查步骤：**

```bash
# 1. 检查Redis中是否有数据
redis-cli KEYS "ecg:lead:config:*"

# 2. 检查Redis序列化配置
# 确保RedisTemplate使用Jackson2JsonRedisSerializer

# 3. 检查CacheWarmer是否执行
grep "缓存预热" logs/cardioguard.log

# 4. 清除缓存重试
redis-cli FLUSHDB

# 5. 重启应用，触发缓存预热
mvn spring-boot:run
```

### 问题4: GC停顿时间过长

**症状：** 应用出现明显卡顿，日志显示GC停顿超过500ms

**解决：**

```bash
# 1. 增加堆内存
-Xms4g -Xmx4g

# 2. 调整G1参数
-XX:MaxGCPauseMillis=100  # 更激进的停顿目标
-XX:G1HeapRegionSize=32m  # 增大Region

# 3. 分析堆转储文件
jmap -dump:format=b,file=heap.hprof <pid>

# 4. 使用MAT或VisualVM分析堆转储
# 查找内存泄漏或大对象
```

### 问题5: 连接池耗尽

**症状：**
```
HikariPool-1 - Connection is not available, request timed out after 30000ms
```

**解决：**

```yaml
# 增加连接池大小
spring:
  datasource:
    hikari:
      maximum-pool-size: 100  # 从50增加到100
      
# 或者优化SQL查询，减少连接占用时间
```

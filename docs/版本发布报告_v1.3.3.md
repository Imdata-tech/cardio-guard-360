## 🔧 技术实现

### 1. Java反射测试私有方法

**挑战:** `generateEcgDataPoint()` 是私有方法,无法直接调用

**解决方案:**
```java
Method method = EcgSimulationService.class.getDeclaredMethod("generateEcgDataPoint", Long.class);
method.setAccessible(true);
Map<String, Object> dataPoint = (Map<String, Object>) method.invoke(ecgSimulationService, userId);
```

**优势:**
- 无需修改生产代码可见性
- 直接测试核心算法逻辑
- 保持封装性

### 2. 大量数据点验证波形特征

**挑战:** 如何验证ECG波形包含P-QRS-T特征?

**解决方案:**
```java
boolean hasHighPeak = false;  // R波
boolean hasLowValley = false; // Q/S波

for (int i = 0; i < 1000; i++) {
    Map<String, Object> dataPoint = generateEcgDataPoint(userId);
    Double voltage = (Double) dataPoint.get("voltage");
    
    if (voltage > 1.0) hasHighPeak = true;
    if (voltage < -0.5) hasLowValley = true;
    
    if (hasHighPeak && hasLowValley) break;
}

assertTrue(hasHighPeak, "应该存在R波高峰值");
assertTrue(hasLowValley, "应该存在Q/S波低谷值");
```

**优势:**
- 统计学验证而非确定性验证
- 适应随机噪声影响
- 高效 (找到即停止)

### 3. 前端Mock外部依赖

**挑战:** WebSocket和axios是外部依赖,测试环境不可用

**解决方案:**
```typescript
vi.mock('axios', () => ({
  default: {
    post: vi.fn(),
    get: vi.fn()
  }
}))
```

**优势:**
- 隔离外部依赖
- 控制测试场景
- 避免网络请求

### 4. 数据缓冲边界测试

**挑战:** 验证500个点限制逻辑

**解决方案:**
```typescript
// 填充500个点
for (let i = 0; i < 500; i++) {
  vm.ecgData.push(i * 0.1)
}

// 添加新点
vm.handleEcgData({ voltage: 1.0 })

// 验证
expect(vm.ecgData.length).toBe(500)
expect(vm.ecgData[0]).toBe(0.1)   // 第一个旧数据被移除
expect(vm.ecgData[499]).toBe(1.0) // 新数据在末尾
```

**优势:**
- 精确验证边界行为
- 验证FIFO队列逻辑
- 防止内存泄漏

### 一、数据库层优化

#### 1.1 MySQL索引优化

**问题分析：**
- 当前只有单列索引，缺少复合索引
- 高频查询字段未充分优化
- 缺少覆盖索引

**优化措施：**

```sql
-- 1. 用户表优化索引
ALTER TABLE sys_user ADD INDEX idx_role_status (role, status);
ALTER TABLE sys_user ADD INDEX idx_create_time (create_time);

-- 2. 设备表优化索引
ALTER TABLE device ADD INDEX idx_user_status (user_id, status);
ALTER TABLE device ADD INDEX idx_serial_number (serial_number);
ALTER TABLE device ADD INDEX idx_device_type (device_type);

-- 3. ECG分析结果表优化
ALTER TABLE ecg_analysis_result ADD INDEX idx_user_created (user_id, created_at DESC);
ALTER TABLE ecg_analysis_result ADD INDEX idx_status_created (status, created_at DESC);

-- 4. ECG标注表优化
ALTER TABLE ecg_annotation ADD INDEX idx_result_type (analysis_result_id, annotation_type);
ALTER TABLE ecg_annotation ADD INDEX idx_user_created (created_by, created_at DESC);

-- 5. 多导联记录表优化（已存在，确认）
-- idx_user_id, idx_device_id, idx_created_at, idx_status 已创建 ✅

-- 6. 健康告警表优化
ALTER TABLE health_alert ADD INDEX idx_user_severity (user_id, severity, created_at DESC);
ALTER TABLE health_alert ADD INDEX idx_status_created (status, created_at DESC);
```

**预期效果：**
- 复合查询性能提升60-80%
- 减少全表扫描
- 降低数据库CPU负载

#### 1.2 查询语句优化

**优化前示例：**
```java
// ❌ 低效查询 - 未使用索引
LambdaQueryWrapper<EcgAnnotation> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(EcgAnnotation::getUserId, userId);
wrapper.orderByDesc(EcgAnnotation::getCreatedAt);
```

**优化后：**
```java
// ✅ 高效查询 - 利用复合索引
LambdaQueryWrapper<EcgAnnotation> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(EcgAnnotation::getCreatedBy, userId)  // 使用idx_user_created索引
       .orderByDesc(EcgAnnotation::getCreatedAt);
```

**优化原则：**
1. WHERE条件字段顺序与复合索引一致
2. 避免SELECT *，只查询需要的字段
3. 使用LIMIT限制返回数量
4. 避免在索引列上使用函数

#### 1.3 连接池优化

**当前配置：**
```yaml
spring:
  datasource:
    # 默认HikariCP配置
```

**优化配置：**
```yaml
spring:
  datasource:
    hikari:
      # 最小空闲连接数
      minimum-idle: 10
      # 最大连接池大小（根据服务器配置调整）
      maximum-pool-size: 50
      # 连接超时时间(毫秒)
      connection-timeout: 30000
      # 空闲连接超时时间(毫秒)
      idle-timeout: 600000
      # 连接最大生命周期(毫秒)
      max-lifetime: 1800000
      # 连接测试查询
      connection-test-query: SELECT 1
      # 池名称
      pool-name: CardioGuardHikariPool
```

**参数说明：**
- `minimum-idle`: 保持10个空闲连接，快速响应突发请求
- `maximum-pool-size`: 根据CPU核心数设置（CPU核数*2+磁盘数）
- `max-lifetime`: 防止连接泄漏，定期回收

#### 1.4 SQL慢查询监控

**启用慢查询日志：**

```yaml
mybatis-plus:
  configuration:
    # 开启SQL日志
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
    
# 日志配置

  level:
    # 慢查询阈值：超过1秒的SQL记录为WARN
    com.cardioguard.mapper: DEBUG
```

**添加性能拦截器：**

```java
@Component
@Intercepts({
    @Signature(type = StatementHandler.class, method = "query", args = {Statement.class, ResultHandler.class}),
    @Signature(type = StatementHandler.class, method = "update", args = {Statement.class})
})
public class SqlPerformanceInterceptor implements Interceptor {
    
    private static final long SLOW_QUERY_THRESHOLD = 1000; // 1秒
    private static final Logger log = LoggerFactory.getLogger(SqlPerformanceInterceptor.class);
    
    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        long startTime = System.currentTimeMillis();
        try {
            return invocation.proceed();
        } finally {
            long executionTime = System.currentTimeMillis() - startTime;
            if (executionTime > SLOW_QUERY_THRESHOLD) {
                log.warn("慢查询检测: 执行时间={}ms, SQL={}", 
                    executionTime, getSql(invocation));
            }
        }
    }
    
    private String getSql(Invocation invocation) {
        StatementHandler statementHandler = (StatementHandler) invocation.getTarget();
        MetaObject metaObject = SystemMetaObject.forObject(statementHandler);
        BoundSql boundSql = statementHandler.getBoundSql();
        return boundSql.getSql();
    }
}
```

### 二、InfluxDB时序数据优化

#### 2.1 数据保留策略(Retention Policy)

**问题：** ECG原始数据无限增长，占用大量存储空间

**优化方案：**

```bash

  --name ecg-raw-30d \
  --org cardioguard \
  --retention 720h \

# 降采样数据保留1年
influx bucket create \
  --name ecg-downsampled-1y \
  --org cardioguard \
  --retention 8760h \
  --description "ECG降采样数据，保留1年"

# 统计数据永久保留
influx bucket create \
  --name ecg-statistics \
  --org cardioguard \

```

#### 2.2 数据降采样任务

**创建Flux降采样任务：**

```flux
// 每5分钟执行一次，将原始数据降采样为每分钟平均值
option task = {
    name: "ecg_downsample_1min",
    every: 5m
}

from(bucket: "ecg-raw-30d")
    |> range(start: -10m)
    |> filter(fn: (r) => r._measurement == "heart_rate")
    |> aggregateWindow(every: 1m, fn: mean, createEmpty: false)
    |> to(bucket: "ecg-downsampled-1y")
```

**预期效果：**
- 存储空间减少90%（从每秒1个点降到每分钟1个点）
- 长期趋势分析性能提升
- 降低存储成本

#### 2.3 写入批量优化

**优化前：**
```java
// ❌ 逐条写入，性能差
for (HeartRateData data : dataList) {
    influxDB.writePoint(buildPoint(data));
}
```

**优化后：**
```java
// ✅ 批量写入，性能提升10倍
List<Point> points = dataList.stream()
    .map(this::buildPoint)
    .collect(Collectors.toList());

try (WriteApi writeApi = influxDBClient.getWriteApi(
        WriteOptions.builder()
            .batchSize(1000)        // 批量大小
            .flushInterval(5000)    // 刷新间隔5秒
            .bufferLimit(10000)     // 缓冲区上限
            .build())) {
    writeApi.writePoints(points);
}
```

**配置参数：**
- `batchSize`: 1000点/批次
- `flushInterval`: 5秒强制刷新
- `bufferLimit`: 10000点缓冲区上限

**预期效果：**
- 写入吞吐量提升10倍
- 减少网络往返次数
- 降低InfluxDB负载

#### 2.4 查询优化

**优化前：**
```flux
// ❌ 查询全部字段，返回大量无用数据

    |> filter(fn: (r) => r._measurement == "heart_rate")
```


### 三、Redis缓存优化

#### 3.1 缓存策略设计

**缓存层级：**

| 数据类型 | 缓存策略 | TTL | 更新方式 |
|---------|---------|-----|---------|
| 用户信息 | Cache-Aside | 30min | 主动失效 |
| 设备状态 | Write-Through | 5min | 实时更新 |
| ECG实时数据 | Write-Behind | 1min | 异步写入 |
| 导联配置 | Cache-Aside | 24h | 手动刷新 |
| 会话Token | - | 24h | 自动过期 |

#### 3.2 缓存实现优化

**添加分布式锁：**

```java
@Service
public class CachedEcgLeadConfigService implements EcgLeadConfigService {
    
    @Autowired
    private EcgLeadConfigMapper leadConfigMapper;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    private static final String CACHE_KEY_PREFIX = "ecg:lead:config:";
    private static final long CACHE_TTL = 24 * 3600; // 24小时
    
    @Override
    public List<EcgLeadConfig> getAllLeadConfigs() {
        String cacheKey = CACHE_KEY_PREFIX + "all";
        
        // 1. 尝试从缓存获取
        List<EcgLeadConfig> cached = (List<EcgLeadConfig>) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return cached;
        }
        
        // 2. 缓存未命中，查询数据库
        List<EcgLeadConfig> configs = leadConfigMapper.selectList(null);
        
        // 3. 写入缓存
        redisTemplate.opsForValue().set(cacheKey, configs, CACHE_TTL, TimeUnit.SECONDS);
        
        return configs;
    }
    
    @Override
    public EcgLeadConfig updateLeadConfig(EcgLeadConfig config) {
        // 1. 更新数据库
        leadConfigMapper.updateById(config);
        
        // 2. 清除相关缓存
        invalidateCache();
        
        return leadConfigMapper.selectById(config.getId());
    }
    
    /**
     * 清除所有导联配置缓存
     */
    private void invalidateCache() {
        Set<String> keys = redisTemplate.keys(CACHE_KEY_PREFIX + "*");
        if (keys != null && !keys.isEmpty()) {
            redisTemplate.delete(keys);
        }
    }
}
```

```java
@Component
public class CacheWarmer implements ApplicationListener<ApplicationReadyEvent> {

    private EcgLeadConfigService leadConfigService;
    
    @Autowired

    }
}
```

#### 3.4 缓存监控

**添加缓存命中率统计：**

```java
@Component
public class CacheMetrics {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    private final AtomicLong hitCount = new AtomicLong(0);
    private final AtomicLong missCount = new AtomicLong(0);
    
    public <T> T getWithMetrics(String key, Supplier<T> loader) {
        T value = (T) redisTemplate.opsForValue().get(key);
        if (value != null) {
            hitCount.incrementAndGet();
            return value;
        }
        
        missCount.incrementAndGet();
        value = loader.get();
        if (value != null) {
            redisTemplate.opsForValue().set(key, value);
        }
        return value;
    }
    
    public double getHitRate() {
        long total = hitCount.get() + missCount.get();
        return total == 0 ? 0 : (double) hitCount.get() / total;
    }
}
```

### 四、WebSocket优化

#### 4.1 连接池管理

**问题：** 当前每个用户一个WebSocket连接，资源消耗大

**优化方案：**

```java
@Component
public class WebSocketConnectionManager {
    
    private static final int MAX_CONNECTIONS_PER_USER = 3;
    private final ConcurrentHashMap<Long, CopyOnWriteArrayList<WebSocketSession>> userSessions = new ConcurrentHashMap<>();
    
    /**
     * 添加会话
     */
    public void addSession(Long userId, WebSocketSession session) {
        userSessions.computeIfAbsent(userId, k -> new CopyOnWriteArrayList<>());
        
        CopyOnWriteArrayList<WebSocketSession> sessions = userSessions.get(userId);
        
        // 限制每个用户的连接数
        if (sessions.size() >= MAX_CONNECTIONS_PER_USER) {
            // 关闭最旧的连接
            WebSocketSession oldest = sessions.remove(0);
            closeSession(oldest);
        }
        
        sessions.add(session);
    }
    
    /**
     * 广播消息给指定用户的所有会话
     */
    public void broadcastToUser(Long userId, TextMessage message) {
        CopyOnWriteArrayList<WebSocketSession> sessions = userSessions.get(userId);
        if (sessions != null) {
            sessions.forEach(session -> {
                try {
                    if (session.isOpen()) {
                        session.sendMessage(message);
                    }
                } catch (IOException e) {
                    log.error("发送WebSocket消息失败", e);
                }
            });
        }
    }
}
```

### 五、JVM优化

#### 5.1 JVM参数调优

**优化配置：**

```bash
# application.yml同级创建jvm.options文件
-Xms2g                          # 初始堆内存

-XX:NewRatio=2                  # 新生代:老年代 = 1:2
```

**参数说明：**
- G1 GC适合大内存（>4GB）和低延迟场景

```java
@Configuration
public class ThreadPoolConfig {
    
    @Bean("ecgAnalysisExecutor")
    public ExecutorService ecgAnalysisExecutor() {
        return new ThreadPoolExecutor(
            10,                         // 核心线程数
            50,                         // 最大线程数

            20,
            100,
            60L, TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(5000),
            new ThreadFactoryBuilder()
                .setNameFormat("websocket-handler-%d")
                .setDaemon(true)
                .build(),
            new ThreadPoolExecutor.DiscardOldestPolicy()
        );
    }
}
```
